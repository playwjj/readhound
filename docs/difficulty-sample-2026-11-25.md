# 难度引擎样例报告（2026-11-25）

地基三件中的第 3 件：**拿真实文章跑一遍难度引擎，验证它能分出难易**。
结论先说：**引擎能工作，而且跑出了一个必须修正的口径问题**（见 §3）。

## 0. 基线与判定规则

- 已知字表基线：统编版会写字表 1–3 年级 + 4 上 = **1,545 字**
  （`wordlists/grade1-4-writing.csv`，逐学期计数与来源标注完全一致）
- 判定（提案 §9：每篇新字约 5 个）：
  PASS = 生字种数 ≤ 8 且字表覆盖率 ≥ 97%；
  REVIEW = 生字种数 ≤ 15；其余 REJECT。篇幅只报告、不参与判定。
- 引擎：`tools/difficulty.py`（纯 Python，无依赖，可复现）。

## 1. 样例 A：文言《龟兔赛跑》（維基大典，153 字）

来源：<https://zh-classical.wikipedia.org/wiki/龜兔賽跑>（伊索寓言 226 则，文言译本）

|  | 未归一 | 繁简归一后 |
|---|---|---|
| 字表覆盖率 | 62.09% | 83.66% |
| 生字种数 | 40 | 12 |
| 生字字次 / 每百字 | 58 / 37.91 | 25 / 16.34 |
| 平均句长 / 最长句 | 10.9 / 17 字 | 相同 |
| **判定** | **REJECT** | **REVIEW** |

归一后仍超标的生字：龟×10、恒×3、乃×2、徐×2、伊、喻、寓、尚、恃、愧、索、遂。
两点值得注意：

- **繁简归一是必备步骤**：不归一，40 个生字里 28 个只是字形差异，
  引擎会把一篇文言短文误判得比实际难得多。入库管线必须先转简体再分析。
- **龟字本身不在 1–4 年级会写字表里**：故事主角的字孩子还没学过写，
  这正是「生字溯源 + 读前预热」要处理的情况，不是引擎的 bug。

## 2. 样例 B：现代汉语解说文《龟兔赛跑》（Giggle Academy，562 字）

来源：<https://www.giggleacademy.com/blog/zh-Hans/learning/storybooks/the-hare-and-the-tortoise-aesops-fables-by-aesop>
（背景介绍 + 道德解读 + 四条教训，非故事正文；作现代汉语对照样例）

|  | 结果 |
|---|---|
| 字表覆盖率 | 90.21% |
| 生字种数 | 33（生字字次 55，每百字 9.79） |
| 平均句长 / 最长句 | **31.2 / 48 字** |
| **判定** | **REJECT** |

生字举例：稳×4、努×3、懈×3、估×2、寓×2、律×2、标×2、盹×2，另有
嘲、毅、碍、驭、赋、障、述、赢等。结论符合直觉：这是写给家长/老师看的
成人解说文，不是四年级故事——平均句长 31 字、单句 48 字本身就超标，
引擎判淘汰是对的。

## 3. 样例跑出的真正问题：会写字表作基线太严

样例 B 的 33 个「生字」里混着两类字：

- 真超纲：懈、驭、赋、障、盹、嘲——四年级孩子确实不认识，判生字没错；
- **假超纲：考、德、基、标、律、译**——这些字孩子大概率会认，
  只是还没轮到「会写」。会写字表（1,545 字）比课标认读量
  （3–4 年级累计 2,500 字）少了约 1,000 字，拿它当已知基线，
  引擎会系统性高估难度、误杀本来能读的文章。

**修正方向（不改提案 §5 的设计，只改数据源）**：

1. 补一份统编版「识字表」（认读字，约 2,500 字到四年级末）作阅读基线；
   会写字表退为第二层（判断哪些字还要练写）。
2. 在那之前，冷启动识字测评（提案 §5 已定为一期必备）是真正的校准器——
   孩子的已掌握字表以实测为准，不以任何标准表为准。
3. 句长信号可用：样例显示成人文平均句长 31 字 vs 文言 11 字；
   儿童故事正文的合理区间待第三篇样例（真正的四年级故事正文）标定，
   暂不写入阈值。
